# Testing

The whole automated test surface is command-line flags on `MikanTrack.exe`: there is no separate test binary and no external test framework. This doc is the map of what exists, how to run all of it in one pass, what each command actually asserts, and where the coverage stops. The flag cheat sheet is in [commands.md](./commands.md), the registry mechanics and the record/replay instrument in [debugging.md](./debugging.md), and the build and working-directory rules in [build.md](./build.md).

---

## Running the tests

Build first. There is one target, and the tests live inside it:

```bash
cmake --build build --target MikanTrack --config Release --parallel
```

Then run from the exe's own directory. Model paths are relative and fail silently from anywhere else:

```bash
cd build/Release && ./MikanTrack.exe --test-fusion
```

Every command follows the same contract:

- exit code 0 means pass, nonzero means fail

- it writes `<flag without the dashes>.log` next to the exe (`--test-fusion` writes `test-fusion.log`), overwritten on each run, in addition to console output

- the log lists every individual check with its measured numbers, so read the log rather than the exit code alone. A shell pipeline can mask an exit code, and the measured values are the part that tells you how close to a threshold a passing check sits.

`./MikanTrack.exe --list-tests` prints the live list grouped by category. It is generated from the registry, so it is never stale, which the tables below can be.

### Running every self-test in one pass

The 37 self-tests are deterministic and need no hardware or input files, so they run as a batch. This drives the list from `--list-tests` rather than a hardcoded list, so a newly added test is picked up automatically:

```bash
cd build/Release && ./MikanTrack.exe --list-tests | awk '/^self-tests:/{f=1;next} /^[a-z]/{f=0} f && $1 ~ /^--/{print $1}' | while read -r flag; do ./MikanTrack.exe "$flag" >/dev/null 2>&1 || echo "FAIL $flag"; done; echo done
```

The full batch takes about 15 seconds and prints nothing but `done` when everything passes. For a failing flag, read its `.log` in the same directory.

Side effects of a batch run: each test overwrites its own `.log` next to the exe, and four of them write scratch files under `%TEMP%`:
- `mikan-test-replay.jsonl` with its `.face.jsonl` sidecar
- `mikan-test-faceprofiles/`
- `mikan_framerecorder_test/`
- `mikanmediapipe_test_dump/`

Nothing touches a project folder, a saved config, or any recording.

## Self-tests: what each one verifies

### Hand pipeline

- `--test-handpose`: `HandPoseModel`. Builds a synthetic right hand by forward kinematics over a hand-authored skeleton, then extracts the palm frame and finger angles back out of the resulting 21 landmarks and checks the round trip closes. Covers moderate curl, a deep fist, thumb opposition, a wrong handedness label, skeleton length recovery, the angle sign conventions (zero-angle bone along the neutral direction, positive proximal, positive lateral, zero-inter collinearity), the metacarpal zero (a hand whose fingers continue their metacarpals reads zero on every angle, a splayed finger reads its splay), a base bone folded past 90 degrees (the lateral stays a splay and the proximal reads past 90, rather than a half-turn lateral with the later bends negative about a reversed hinge), a base bone exactly on the palm normal (the lateral comes from the finger's bend plane, where the projection has no length), and FK reprojection error.

- `--test-handestimator`: `HandStateEstimator`, the angle-space multi-view state estimator, in 13 lettered cases. Synthetic cameras project a known FK hand and the estimator has to recover and track it from 2D landmarks alone: clean two-camera recovery from a perturbed seed, tracking a moving hand under pixel noise, camera dropout without a step, a mono stretch where lateral motion tracks and depth stays leashed, bit-identical determinism across two runs, the divergence guard dropping garbage correspondence, an unchanged observation not moving the state, mono depth-bias drift being resisted, the joint-limit prior, DIP-PIP coupling, the fitted angle prior discriminating a snap from a pose change, the innovation gate holding teleports while tracking fast real motion, and rows weighted by measured confidence rather than presence.

- `--test-fusion`: `HandFusion` end to end, in cases (a) through (t). Two-camera fusion beating both noisy inputs, dominant-camera choice, staleness passthrough, handedness-mislabel recovery, stereo hand-scale correction, ray-aware clustering, the spatial side prior, joint cluster pairing (a regression from a captured clap dump), the decisive-disagreement veto, slot side-collision ordering, stability weighting, stereo landmark triangulation with its residual gate and veto, solo-cluster rescue, triangulation pair choice by geometry, camera loss with mono depth error, and side-assignment refusal with post-window reacquisition.

- `--test-pnp`: monocular PnP in `LandmarkTo3D`, and the palmar side of a hand whose side is decided: a flat left hand with its thumb on the back of the palm plane takes the wrong side from its evidence and the right one from a decided side, in the lift and in the direct solver's finger measurement. One synthetic all-21 pose recovered to sub-millimetre, plus a real frame captured live where a flat waving hand made the object model near-planar and the old ITERATIVE cold start collapsed the depth. That second case is a pinned regression for the SQPnP cold path.

- `--test-seeding`: the positional half of the cross-camera seed decision, `HandTrackingPipeline::isSeedRedundant`. Hints inside a tracked box, hints inside the projection-error margin, hints beyond it, inflation applied about the box centre rather than the origin, and two tracked boxes each able to absorb a hint. Then the body hints: `makeBodyHandHints` on two synthetic whole-body hands gives two hints at the palm center with the wrist to middle knuckle direction and length, a body hint's seed detection gives the ROI `HandRoi::fromLandmarks` gives the same landmarks, a hand scored under the gate gives no hint and keeps its box, a hand scoring under a half on average or on a body wrist the model cannot see gives none either. The backoff, `BodySeedBackoff`: a refused seed closes its own place and no other for the first wait, each refusal of the same place doubles the wait up to its cap, a place left alone past its memory starts over, and a seed the hand model kept reopens it, and a palm center off the frame or an observation without the blocks gives none. And the eviction rule, `chooseSlotToEvict`: the slot on neither whole-body hand gives way at either index, two slots on whole-body hands or within their margin give none, two off both give the lower presence, and no whole-body hand gives none. The rest of the seeding path needs the ONNX models, so only these parts are isolated. Last, the hand side by shape, `matchHandSideByShape`: two whole-body hands on one wrist pixel that differ by shape alone give each slot its own hand, a slot no nearer one hand by the margin has no side, and a hand under the score gate, an observation without the blocks or a slot with no size leaves it undecided. With the hands apart, a slot inside the distance bar of the nearer hand has its side and one past the bar from both has none, the margin notwithstanding. Then `correctHandSides` on the same hands: two slots under crossed labels change places and two under their own stay, a single slot under the wrong label moves, of two slots on one hand the nearer takes the side and a tie moves nothing, an undecided slot takes the side a decided one leaves, slots past the bar from both hands are not moved under either label, a slot within the bar of the one scored hand moves to it when its own label's hand is unscored and stays past the bar or when its own label's hand scores, and both hands under the gate, an absent block or a slot with no size move nothing.

- `--test-bonecalib`: `HandBoneCalibrator`. Noise-free recovery of known phalanx and base lengths from triangulated landmark samples, recovery under 4 mm landmark noise with the length bias and spread reported, the object model PnP builds from a calibrated skeleton, and the minimum-sample gate.

- `--test-deskhand`: `DeskHandCalibrator`, the one-camera bone path. A flat synthetic hand on the raised desk plane seen by a calibrated camera recovers its skeleton to within a hundredth of a millimetre and a lift depth scale of 1, a hand tilted 40 degrees off the desk is refused by the flatness gate, and a landmark model whose articulation disagrees with the pixels (curled model points under a flat hand) measures a lift depth scale away from 1 with a small spread, which is the bias the scale exists to calibrate out.

- `--test-angleprior`: `AnglePriorCalibrator`. Samples a known generative model with two latent synergy factors and checks the calibrator recovers the mean and the correlation structure, since the structure is what makes a coordinated pose change cheap and an uncorrelated single-DoF snap expensive under the Mahalanobis metric. Also covers the minimum-sample gate and the variance floor that keeps an unexercised DoF soft.

- `--test-roiquality`: `HandRoiQuality` and the per-camera `LumaFlickerTracker`. Uniform and clipped ROIs, noise separated from sharpness, resolution independence across a scaled frame, a degenerate ROI rejected, and flicker instability measured on a rippling frame against a steady one.

### Body pose

- `--test-bodypose`: `BodyPoseSolver`, the largest self-test at roughly 60 checks. Everything the solver produces comes from 2D rays plus known body lengths, so each case is constructed exactly and checked to sub-millimetre: known-separation depth, shoulders from their own rays plus the calibrated width, the elbow as a ray against the bone circle, the occluded elbow carried by continuity, the negative control proving that holding the elbow position instead would break the bone length, a fast swing returning to the right root, a contradicting ray not overruling continuity, the shoulder ray breaking the cold-start tie, grazing-ray clamping and continuity across tangency, held observations still publishing, IMU forearm precedence left untouched, the head from two ear rays plus head width including yaw recovery and the implausible-range gate, the visibility gates, the landmark-mask round trip, and the whole-body blocks: a synthetic 133-point model result through `BodyPoseTracker::fillObservation` lands the face and each hand under the model's own indices with side 0 the left hand, the blocks survive the JSON round trip, and an observation without the key or from the planar backend has none. Last, the face shape ratios on a synthetic iBUG face: they read the same at twice the size, rolled and shifted, each is its distance over its span, a closing eye, an opening mouth and raised brows each move their own ratio alone, and side 0 is the person's left eye.

- `--test-bodycalib`: `BodyDimensionCalibrator`. Projects a synthetic body of known landmark separations, deliberately away from the anatomical defaults, and checks the calibrator measures those separations back: shoulder width, head width, nose-forward offset, upper arm derived from shoulder width, the raised-hand acceptance gate rejecting hands out on the desk, a solve from one raised hand, the too-few-samples gate, and the face-on head rejection.

### IMU

- `--test-imufilter`: `ImuOrientationFilter`, the orientation EKF, in cases (a) through (q). Static gravity-only bias learning including the deliberately unobservable gravity-axis component, the same case aided by vision, sustained rotation tracking, the accelerometer motion gate, yaw observability before and after vision, the mounting calibration round trip, motion-based arm-axis recovery, the two-motion mounting solve, twist gating, the gyro bias bound, the axial residual as a mounting-roll health check, pose-averaging the mounting, yaw covariance re-inflating while coasting, palmar-side temporal stability, flip hysteresis, and the curl strength gate.

- `--test-imudiscovery`: the invariant that `ImuService` device discovery never blocks its caller, since `ImuService::update()` runs on the vision thread. Asserts startup under 50 ms, worst single update under 20 ms, shutdown joining within 3 s, and a clean restart cycle. Hardware-independent by design: HID enumeration runs whether or not a controller is paired. See the known flake below.

### Calibration

- `--test-charuco`: the intrinsics wizard path. Bare Charuco finder construction, an ONNX pipeline startup that mirrors live app state, `MonoLensDistortionCalibrator` construction and `update()` against synthetic frames, capture progress on a rendered board including a second capture after an immediate fast board move, and synthetic intrinsics recovery checked against the true horizontal FOV and a sub-hundredth-pixel reprojection error. The ONNX step is a smoke check that the pipeline starts alongside the calibrator, not an inference assertion.

- `--test-extrinsics`: the extrinsics wizard math. An Aruco marker rendered into a synthetic camera 0.8 m above the world origin, then marker distance, recovered camera height, `ExtrinsicsWizard::raycastPixelOntoPlane` onto the table, and the marker axes fixing the world frame rather than only the origin. A second section covers `ExtrinsicsValidation` cross-camera scoring: perfect observations score near zero, and a one-degree orientation error on one camera is flagged by the spacing check even though reprojection alone nearly hides it.

## Hardware tests

These need a device physically connected to mean anything, so they stay out of the batch:

- `--test-joycon`: Joy-Con sample decode against hand-built report bytes with known values, then live HID streaming.

- `--audio-probe [seconds] [--device name] [--gate dbfs] [--gain db]`: runs the microphone mouth stage on a capture device for a few seconds and reports the level, the gate, the backend's info line and run time, the frames per second, and the dominant viseme of each polled frame, then runs the calibration wizard's capture tap for a second and reports the samples collected, the calibration frames that passed the gate, and the gate the clip suggests, passing when the device opened, the backend is ready, frames arrived, and the tap collected at least half a second. A `--gate` under the room's noise floor makes the backend run in a quiet room, which is how the chain is checked without speaking.

- `--test-imuaxes`: measures whether the gyro axes are consistent with the accelerometer axes on a live controller, by scoring every signed permutation against `dg/dt = -w x g`. A mounting calibration can absorb a fixed rotation but not an axis permutation or sign flip inside the chip.

- `--test-vrm-samples`: loads the shipped VRoid sample avatars from `models/avatars/` and checks the full humanoid map, valid hand rests, a T-pose with palms down, and bounded skins, plus the `aa` and `blink` expressions and a SHA-256. Skips with a warning when the files are absent.

- `--test-posemodel`: loads the body-pose ONNX models (both landmark backends, the whole-body one skipped when absent) and cross-checks the body decode against keypoints from the Python reference implementation. It needs `models/` and a working execution provider rather than a camera, so it is the one that tells you an inference-stack change is at fault rather than tracking logic.

## Tools with regression value

The `Tool` category commands take a file argument, so they are not part of any automated pass, but two of them are the strongest regression instruments in the repo when a recording is available:

- `--replay-verify <recording.jsonl>` re-runs a recording and exits 0 only when every frame's replayed checksum matches the recorded one. This is the real coverage for `LandmarkTo3D` and `HandFusion` against live data rather than synthetic fixtures. Checksums are a same-binary guarantee: a divergence after a change that touches those stages is the diff of the change, not corruption, and a divergence after an unrelated rebuild is not by itself evidence of a bug.

- `--replay-popmetrics <recording.jsonl>... [prior-config.json]` reports pop statistics of a recording, baseline against the hand estimator, which measures a smoothing or estimator change rather than only detecting that it changed something.

- `--replay-mono-baseline <recording.jsonl>... [cameraIndex] [frames.csv]` replays each recording faithfully and again with one camera alone and no IMU overlay, then measures the single-camera palms, fingers, elbows, shoulders and head against the stereo-triangulated output of the same frames, with the palm error split along the camera's view ray and lateral to it and the frame-to-frame palm steps of both passes. The optional CSV holds one row per compared hand and frame, including the camera's own lift and label of that hand and the FK reprojection of both poses against its pixels, which is how a bias is attributed to the landmarks, the lift, or the fit. It exits 0 only when the pooled numbers pass the single-camera plan's gates (palm error p50 under 3 cm and p90 under 8 cm, elbow root flips under 2 percent of model frames, finger angle error p50 under 10 degrees), so it is the regression check for anything that changes what one camera can do.

- `--gate-direct <recording.jsonl>... [cameraIndex] [correct] [mirror=<enter>,<leave>] [frames.csv]` is the single-camera direct mode's measurement (with `correct`, on the camera's hands with their sides corrected from the recorded whole-body hands ahead of the lift, as the live direct camera corrects them, reporting the frames a hand was moved on, and with `mirror=<enter>,<leave>` at those palm mirror bars in place of the configured ones): it re-runs the whole-body 3D backend over one camera's raw frames (so the recording needs them) and compares the arm segment directions it would retarget from against the faithful replay's arms (triangulated wrists, IMU forearms where recorded, the body solver's shoulders), carried into that camera's frame. The model's depth is relative to the hips, so each arm is lifted three ways: at the root depth that best fits the truth (the model's own direction error, depth scale solved away), at the root depth the pixel shoulder width implies against the configured width (what the live mode would have), and at the fitted depth with every relative depth zeroed (what a planar model gives, so the depth axis's contribution shows). It reports direction error, elbow and wrist error, bend flips (the elbow's offset from the shoulder-wrist line pointing against the truth's), the planar pixel agreement per joint, the live root depth's error, the model's wrist-to-shoulder depth against the truth's (sign agreement and scale, on frames where the truth separates them by 10 cm), and direction steps between model frames for both. It exits 0 only when the pooled numbers pass the gates set from the first webcam-position take (shoulder pixel error p50 under 15 px, wrist under 80 px, live root depth error p50 under 10 cm, wrist depth sign agreement at least 75 percent). The gates cover what the truth measures independently of the model, the stereo wrist and the ray-and-width shoulder. The truth elbow is not that: without an IMU it comes from the body solver through the body-pose camera's own 2D elbow, so the direction and bend-flip numbers are reported without a gate until a take with the IMUs worn sets them. It also runs the avatar retargets on the shared synthetic rig: the position retarget over the replayed fused frame is the reference, and two candidates run over the camera's recorded hands and the re-run observation under the recording's direct config, the direct retarget and a Kalidokit-style baseline (`src/Tests/KalidokitStyleRetarget`, the webcam vtuber tools' pattern: the model's own 3D landmarks as directions with the relative depth stretched by the measured 0.6, each bone swung onto its direction, the hand from the hand model's palm plane, every bone slerped 0.3 toward its target per frame, no bone lengths and no holds). Per side and candidate it reports against the reference the posed upper-arm and forearm direction differences in the direct world, the wrist rotation difference in the forearm and the mean proximal finger difference in the hand, then two metrics that need no truth: the posed avatar's shoulder, elbow and wrist projected into the camera (the avatar's shoulder midpoint on the model's shoulders at the depth the avatar's width implies) against the model's landmarks, the wrist against the hand model's wrist where the direct solver admits it, p50 and p90 in px (the direct retarget's chain is in the user's lengths and its avatar in the avatar's, so its elbow and wrist numbers measure the proportion mismatch as much as the solve); and the rotation of each arm bone between consecutive frames, the jitter, p50 and p90 in degrees. For the direct retarget alone, its wrist's distance along the view ray against the reference's shoulder-to-wrist vector on that ray (cm in the user's units, magnitude and signed), and the hand lift's depth scale it ended the take on. Behind them the camera's own palm frame against the fused one (and the nearer of that palm and its mirror along the view ray, the lift's depth ambiguity the solver undoes by the forearm) and the single view's finger angles as the direct solver measures them against the fused ones (a spread rather than an error, since the fused angles carry the desk setup's rest zero and the direct ones none). None of these is gated. A recording whose camera has no extrinsics (a direct-mode take) has no stereo truth: the tool runs the candidates alone, reports the two truth-free metrics and exits 0 with nothing gated. Either way it counts, per hand, the direct solve's forearm twist steps over 90 degrees between consecutive frames that read the hand, the frames that took the lifted palm's mirror and the frames a hand cut by the frame's edge was held (which do not count as read), and the CSV carries each frame's twist, mirror choice and mirror gain. The measurements are recorded in [LEARNINGS.md](../../LEARNINGS.md). Each twist jump is put down to what changed in the camera's hand over the three frames before it, the first that applies: another slot under the side, the solver's mirror toggling, the lift's palmar side flipping, or the lifted finger axis's lean changing sign. The report also counts the lifted frames whose palmar side is the one the hand's side names, the same for the palm frame the solver's fingers are measured against, and the CSV carries the cause in `directTwistJumpCause`.

		Each is compared as a turn from the rest window's pose. The phone's turn and the camera's are one turn seen in two frames, so the one rotation that best carries the phone's rotation vectors onto the method's is solved over the windows' frames first, and the error is what remains. Reported per method and window: how often it reads, the error p50 and p90 over every frame and over the frames the phone turned 10 degrees or more, its turn's size over the phone's, and whether a mirror would carry the phone's turns better than any rotation with the error under it (what a phone axis read with the wrong sign would look like). `headlag=<ms>` reads the phone that much ahead of the camera. The six-point fit is also compared against the ear and nose head with no phone in it, which says whether the camera heads agree with each other.

	- Hands, when the camera has extrinsics: the truth is the fused hands the rig triangulated, projected into the camera. A fused hand one camera alone supplied is left out, since it is that camera's own slot, a scene false positive included. It reports the whole-body hand's wrist and index, middle and pinky knuckles against the fused hand's in px and palm lengths, how often the whole-body hand's box holds the fused palm (what a search hint needs), the overlap of the camera's hand slot box with the whole-body hand's, and the slot's side by two rules against the fused side: the hand's shape (the mean distance over the 21 points to each whole-body hand, the nearer one by a 0.8 margin and within half a palm length) and the direct solver's wrist test. The side numbers are repeated for the frames where the fused wrists are within one shoulder width of each other.

	- Hand labels, on any camera: the hand slots the direct solver's wrist rule turns away on the other arm's wrist (tracked, not within half a shoulder width of the label's own usable body wrist, within it of the other), read from the recorded whole-body blocks when the take carries them and from the model re-run at the live divider otherwise. Each turned-away slot frame is split by what the hands were doing, from the two body wrists (clasped within half a shoulder width, crossed with the left wrist past the right along the shoulder line by 0.15 shoulder widths, close within one, free and apart, one wrist unseen), and by what the slot was, from its mean distance over the 21 points to each whole-body hand with half a palm length as the bar: on the other arm's hand with both whole-body hands scoring, on it with the label's own hand unscored, on no hand, or undecided. It adds whether `rightProb` names the true side on the slots on the other arm's hand, the frame's other slot, the run lengths, the turned-away slots' distance to the nearer whole-body hand, the accepted slots' distance to their own, and the slot frames accepted under the wrong side. It then puts the same frames through the solver's gate twice, with the slots as published and with `correctHandSides` applied first: the slot frames turned away and how many of them are within the bar of the other arm's hand, the frames with a hand through the gate per side, the slot frames moved, and the side changes of a tracked slot. With extrinsics it adds each kind's fused side. `labels` runs this report alone: from the recorded blocks with no model pass, or after the live-cadence pass only.

	- Body hints: the hand pipeline re-run over the raw frames as the direct camera runs it, with no cross-camera hints, once without and once with the body model's hints (each frame's hints from the previous frame's observation at the live divider, under the live retry throttle). Needs no rig: it reports the tracked slots whose box touches neither whole-body hand's, per side how often a scored whole-body hand has a slot on it, the pipeline's time, and the body hints' funnel with its evictions. With extrinsics it adds, against the triangulated hands, how often each hand has a slot within a palm length of it, the dropouts that ended with the frames to the slot's return, and the slots on neither hand.

	The optional CSV holds one row per model frame of the every-frame pass with the ratios and the phone's columns at the frame's own time. Each face model candidate that ran writes its every-frame eye series beside it, the CSV's name with `_rtmpose_m`, `_rtmpose_t` or `_mediapipe` appended. The body hint re-run writes `_seeds`, one row per hint handed over: its side, palm center, palm length and distance from the frame edge, the body model's scores for the hand and the wrist, whether a slot already sat on it, and what the frame's funnel did (seeded, evicted, kept, dropped).

- `--retarget-golden <recording.jsonl>` is the same comparison over a recording, on the shared synthetic rig with default rig settings so it pins no avatar file. A direct-mode take drives `DirectRetarget` and the stream of its pose from the direct camera's replayed result. Any other take drives the stream from the replayed fused output four ways: `AvatarRetarget` alone on the unresolved frame (which covers the root follow the stream does not carry), the stream with an avatar on every frame, the stream with no avatar on every frame, and the stream with an avatar on only the frames the recorded send rate passes. It exits nonzero on the first frame that differs and names the field. On a direct take the compare runs the live side at the frozen palm mirror rule, and the tool first reports how many of the frames with a palm read the take's own bars change the mirror on, the one deliberate difference a real take reaches.

- `--viseme-bench <clip.wav> [out.json] [options]` is the audio stage's measurement: it runs a mouth model (`--model loudness|mfcc|ovrlipsync`, `mfcc` by default, with `--profile` for a profile and volume-only without one) over a clip under the live rolling-window policy and reports the share of frames each viseme dominated, the chunked frames' mean absolute drift from one whole-clip run per viseme (beside each viseme's mean activity, so the drift reads relative to motion), the per-run inference p50, p95, and max against the hop (`LATENCY PASS` or `FAIL`), and the share of real time the runs took. The JSON it writes holds the `offline`, `chunked`, and `filtered` frame series for `--render-mouth`, which renders a contact sheet of an avatar's face under them through the avatar's Auto face profile, the headless way to judge what the visemes do to a real mouth, preset or perfect sync. The clips `InitialSetup_x64.bat` fetches into `resources/audio/bench/` are the standing inputs; the measured verdicts are in [audio.md](./audio.md).

The remaining tools (`--replay-dump`, `--replay-bodypose`, `--replay-hands`, `--replay-extrinsics`, `--calibrate-bones`, `--fit-angle-prior`, `--test-imupair`, `--vrm-info`, `--render-mouth`) are diagnostics and fitting utilities, not pass/fail checks. `--render-avatar <file.vrm> [out.png]` renders an avatar's rest pose through the real scene renderer from a hidden window (`HeadlessGlContext`, `src/Render`), the regression instrument for the skinned renderer: compare its PNG before and after a shader or draw-order change. `--pose-report <recording.jsonl> [frameIndex] [outDir]` is the static-pose loop after a direct solver change: it replays a direct-mode take or a dump's `dump.jsonl`, holds one frame (the last by default) for 60 solves at the recorded interval so the filters settle, under the recorded config and the avatar at its `modelPath`, and writes `pose-report.json` (the solve state and the posed avatar, the dump's serializers) and `pose-report.png` (the frame from the take's frame directory or the dump's raw PNG with the landmarks and the posed skeleton, beside the avatar rendered from the camera through the same scene renderer). The log carries per joint the posed avatar's reprojection against the body and hand landmarks in px, each arm's elbow and wrist bend, the wrist's distance along its ray with the reachable interval, the model's depth prior and the lift's distance, and the measured and filtered finger angles. An arm whose wrist the body model gated out rests, and the report says so by its missing chain. `--export-board` and `--export-marker` write a PNG and open it in the system viewer, so keep them out of any batch.

## Before and after a refactor

1. Run the full self-test batch on the pre-change build and confirm it is green. A test that was already failing is not evidence about the refactor.
2. If a recording exists and the change touches `LandmarkTo3D` or `HandFusion`, run `--replay-verify` on it before the change so the recorded checksums are known to match the current binary.
3. Make the change.
4. Re-run the batch. `--test-handestimator` case (e) and `--test-replay` case (a) are the two determinism assertions: if a refactor introduced wall-clock, iteration-order, or floating-point-order dependence into a replayed stage, they are where it surfaces.
5. Re-run `--replay-verify`. A pure refactor of a replayed stage must leave the checksums matching, which makes this the sharpest available test that behavior did not change. A divergence means the refactor was not behavior-preserving.
6. If the change touches the retarget path (`AvatarRetarget`, `DirectRetarget`, `AvatarRetargetMath`, `VmcRetarget`, `OscStreamer`), `--test-retarget-golden` is in the batch, and `--retarget-golden` runs on one fused take and one direct take. `--replay-verify` is no evidence here: its checksum is taken before the retarget runs, and no recording holds an avatar pose or a VMC packet.

## What the tests do not cover

Worth knowing before relying on a green batch:

- `VisionThread` orchestration. `--test-replay` reproduces its call sequence in a single-threaded test, so the sequencing is covered but the threading, the frame-pop path, the hitch watchdog, and the config-refresh handling are not.

- Video capture. Nothing under `src/Video` (the WMF backend, device enumeration, mode selection) has a test.

- Inference itself. `PalmDetector`, `HandLandmarkModel`, `SsdAnchors`, and `OnnxSession` are exercised only as a startup smoke check by `--test-charuco`, and only `--test-posemodel` numerically checks a decode, on the body models. Every hand-side test starts from landmarks that a test fixture generated, not from a model.

- All rendering and UI. `src/Render` and `src/UI` have no coverage beyond the localization tables and the wizard math that `--test-extrinsics` calls directly.

- Config and project persistence. `AppConfig`, `ProjectManager`, and `GlobalSettings` round trips are not tested, though the replay test does reconstruct an `AppConfig` from a recording header.

- Assorted library code with no direct test: `OneEuroFilter`, most of `src/Math`, `src/Utility` (`PathUtils`, `StringUtils`, `WorkerThread`), and the `UdpSocket` send path to a remote host (`--test-vmc` decodes the bytes the streamer builds, but never puts them on a socket).

## Known flake

`--test-imudiscovery` fails when HID enumeration is cold. Case (a) allows `ImuService::shutdown()` 3 s to join a worker that may be mid-enumeration. With no Joy-Cons paired and no recent enumeration, that join has been measured between 4.5 s and 10.1 s, which is the first run of a batch every time on at least one dev machine. Run it again immediately and the join settles at about 3 ms and passes.

The flake signature is a `shutdown must join promptly` line in `test-imudiscovery.log` with the startup and worst-update times well inside their thresholds. That is the enumeration being slow, not a regression: re-run it. A failure naming `discovery must not block the caller` is the invariant this test exists for and is never the flake.

## Adding a test

One file under `src/Tests`, holding the function and the `MIKAN_REGISTER_TEST(flag, description, category, function)` line directly below it, including `TestCommon.h` for the shared include block. Then re-run CMake: the target's sources come from a plain `file(GLOB)`, so a new file does not link until a reconfigure. The registry mechanics are in [debugging.md](./debugging.md).

Pick the category honestly. `SelfTest` means deterministic with no hardware and no input files, which is what makes the batch above safe to run unattended, so anything that needs a device or a file belongs in `Hardware` or `Tool` instead.
